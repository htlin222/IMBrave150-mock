# live-demo — 一關一關，把真實世界資料做成一篇論文

> **給 Agent 的入口檔。** 使用者只會說一句「follow the ./live-demo mission by mission」，
> 你要從這裡開始，照著章節順序一關一關做。**先把這份 README 讀完再動手。**

這是 `claude-demo/`（動畫投影片）的**實作版**：投影片是「演」給觀眾看，
live-demo 是**真的做一遍**。章節編號與投影片的六幕一對一。

## 🎬 節奏協定（最重要，違反這條會毀掉現場）

現場有觀眾。講者需要在每一步之間對觀眾說話。所以：

1. **一次只做一個 Mission。** 做完就停。不要因為「下一步很明顯」就順手做掉。
2. 每個 Mission 做完，依序完成三件事：
   - 跑該章的驗收指令（見下方「驗收」）
   - 用**三到五行中文**說「這一步我們看到了什麼」——講**發現**，不是講你用了什麼函式
   - **停住**，輸出一行 `⏸ Mission X.Y 完成，等候指示。`
3. 等使用者說 `next` / `繼續` / `下一關` 才做下一個 Mission。

### 指令表

| 使用者說 | 你要做 |
|---|---|
| `next` / `繼續` / `下一關` | 做下一個 Mission |
| `skip` | 跳過這關，並提醒後面哪些 Mission 會受影響 |
| `why` / `解釋` | 展開講**原理**（為什麼要這樣做），可以用術語，**不要趁機往下做** |
| **`?`** / **`???`** / **`蛤`** / `什麼意思` | **事後白話重講** ↓ |

**`?` `???` `蛤` = 觀眾聽不懂了**，通常是講者代替台下發問。你要：

1. **不要往下做任何事。** 不跑新指令、不改檔案。
2. 用**完全不含術語**的話重講**剛剛那一關實際發生了什麼**：
   我們手上原本有什麼 → 我做了什麼動作（用生活比喻）→ 結果變成什麼、那個數字什麼意思。
3. **三到六句，口語。** 對象是完全不懂統計的臨床醫師。
4. 有關鍵數字的話，用一句話說「這個數字大或小代表什麼」。
5. 結尾回到暫停狀態：`⏸ Mission X.Y 完成，等候指示。`

`why` 是「**為什麼**要這樣做」（方法學，可用術語）；
`?` 是「剛剛**到底發生了什麼**」（事後回顧，不准用術語）。
`???` 比 `?` 更急——從**這一章開頭**重講，不只是這一關。

### 不要做的事

- ❌ **不要偷看參考解。** repo 根目錄有 `harmonize_hospitals.py`、`psm_imbrave150.py` 等
  完成品。只有在 Mission 標示「🆘 卡住時」而且你**已經自己試過至少一次**之後才可以看。
- ❌ **派審稿 subagent 時（Mission 7.1），禁止它們讀 `live-demo/` 的任何檔案。**
  這裡寫著全部的標準答案和地雷清單。讀了就不是審稿，是對答案。
- ❌ **不要動 repo 根目錄的任何檔案。** 所有產出寫進 `live-demo/workspace/`。
- ❌ **不要憑印象寫數字。** 每個數字都要是這一輪真的跑出來的。手稿階段會被稽核。
- ❌ 不要一次寫一個三百行的大腳本把整章做完。一個 Mission 一支小腳本。

## ⚡ 用 subagent 加速

有些 Mission 裡面本來就是「同一件事做 N 次」——那種**派 subagent 平行做**，
省下來的都是台上的真實時間。但它不是萬用加速器，用錯地方會讓現場更慢更亂。

### 三條規則

1. **只在一個 Mission 內部平行，不准跨 Mission 搶跑。**
   節奏協定沒有例外：subagent 收完工，你還是要跑驗收、講三五行、然後 `⏸ 停`。
   「反正 subagent 閒著」不是提前做下一關的理由。
2. **subagent 的回報不算數，驗收腳本才算數。**
   它們回來的東西你要自己合併、自己跑 `verify/`。有 subagent 說「我做完了」
   而驗收 `✗` 的情況，以驗收為準。
3. **⛔ subagent 一律禁止讀 `live-demo/` 底下的任何檔案。**
   這裡寫著全部的標準答案、地雷清單與預期數字。Mission 7.1 的審稿人讀了
   就不是審稿是對答案；其他關的 subagent 讀了則會直接抄答案，失去示範意義。
   派工時把這句話寫進 prompt，不要假設它們不會去翻。

### 值得派的關卡

| Mission | 怎麼切 | 大概省 |
|---|---|---|
| **1.1** 診斷三種方言 | 3 個 subagent，各負責一個 EHR 家族（Alpha／Beta／Gamma），各自回報欄位名、單位、編碼，你再合併成一份差異清單 | 2–3 分 |
| **6.8** 引用驗證 | **每一筆參考文獻一個 subagent**：各自 WebSearch 找真文獻 → Crossref 驗 DOI 與六個書目欄位 → 回報「驗過／驗不過」。這關是網路 I/O，序列跑最慢，平行收益最大 | 5–8 分 |
| **7.1** 四個審稿人 | 本來就設計成平行的（見 [07-review.md](07-review.md)） | 8–10 分 |
| **8.2 + 8.3** PDF 與 DOCX | 兩條 build 沒有相依，可以同時跑 | 2 分 |

### 不要派的關卡

- **1.2 / 2.3 / 3.x / 5.x** —— 這些是「一支腳本跑一次」，切開只會多出合併成本和不一致風險。
  120 種設定是腳本裡的迴圈，不是 120 個 subagent。
- **6.3 → 6.4 → 6.5 → 6.6 → 6.7** —— 寫作順序本身就是方法論（Discussion 先、
  Introduction 後、Abstract 倒數第二、Title 最後）。平行寫等於破壞這一章要教的東西。
- **任何有前後相依的關**。省 30 秒、換一次台上除錯，不划算。

### 給講者的提醒

平行 subagent 的輸出會交錯，畫面會變亂。**那正是講話的空檔**——
派完工就轉頭對觀眾說「它現在同時開了四個獨立的審稿人，彼此看不到對方的意見」，
講完剛好收工。

`workspace/` 一開始是空的。Mission 0.1 會請你把十家醫院的原始 CSV 複製進去 —— 這是

因為 `verify/` 會去找它們。

## ✅ 驗收

每章有一支驗收腳本。做完一個 Mission 就跑它：

```bash
cd live-demo && ../.venv/bin/python verify/ch02.py --mission 2.3
```

輸出長這樣：

```
  ✓ matched.csv 存在
  ✓ 配對數 706 對（允許 666–746）
  ✓ 配對後 |SMD| 全部 < 0.10
  ─────────────────────────────
  PASS  Mission 2.3
```

- **`✗` 就是沒過。** 不要解釋成「大致上對」，回去修到過為止。
- 跑整章：`--chapter`；跑全部：`../.venv/bin/python verify/run_all.py`
- 驗收的容忍區間是刻意設寬的（演算法細節不同會有小差異）。**但如果你的數字掉出區間，
  那不是容忍度太嚴，是你做錯了**——通常是踩到該 Mission 標的地雷。

## ⛔ 全域硬性約束（動手前必讀，違反即失敗）

這些不是建議。它們是**已知會在現場炸掉、而且零教學價值**的東西，
已經幫你擋在前面了——照做就不會遇到。

| # | 約束 | 為什麼 |
|---|------|--------|
| 1 | **不要用 `lifelines.plotting.add_at_risk_counts()`** | 本機 `lifelines 0.30.0` + `numpy 2.5.1` 會拋 `TypeError: only 0-dimensional arrays…`。[Mission 3.2](03-survival.md) 有已驗證的手工替代碼。**不要 debug，不要降版。** |
| 2 | **`matplotlib.use("Agg")` 要在 `import pyplot` 之前** | 否則某些機器會卡住等視窗，畫面靜止。 |
| 3 | **`CoxPHFitter.fit()` 只餵 `[時間, 事件, 共變數]`** | 整張 DataFrame 丟進去會因字串欄爆掉，或被自動 dummy 化成你沒打算跑的模型。 |
| 4 | **IPTW 的 Cox 一定要 `weights_col=` 且 `robust=True`** | 少了 `robust=True` 不會報錯，只會讓標準誤嚴重低估——**點估計對、CI 錯**，最難察覺。 |
| 5 | **任何 pandas 合併之後 `assert len(df) == 預期`** | join/concat 出錯不會拋例外，只會靜靜多幾列或少幾列。 |
| 6 | **不要 `dropna()`。** 第 01–02 章任何形式的 drop 都是錯的 | 缺失不是隨機的（見下方地雷 1）。 |
| 7 | **Crossref 請求一定要帶 `mailto` 的 User-Agent** | 匿名請求會被限流，然後你卡在台上。 |
| 8 | **pandoc 一定要加 `--citeproc`** | 忘了不會報錯，`[@key]` 會原封不動印在 PDF 上。 |

每個 Mission 底下還有自己的 `⛔ 硬性約束` 區塊——**在寫該關的第一行程式碼之前讀它。**

### 地雷分兩類，看標記

| 標記 | 意思 | 你該怎麼做 |
|---|---|---|
| 🛡 **預防** | 純粹的時間黑洞，沒有教學價值 | 照 ⛔ 區塊做，讓它不要發生 |

## ⚠️ 全域地雷（每一章都適用）

1. **AFP 是這份資料的頭號陷阱。** Gamma 那三家醫院（H03/H06/H09，共 560 人）
   **完全沒有連續 AFP 值**，只有 `afp_high` 這個 ≥400 的門檻。併檔後 `afp_ng_ml`
   有 **35.3%** 缺失，而且缺得**不是隨機的**——是整整三家醫院。
   任何模型只要用了連續 AFP 又做 complete-case，就會**無聲地刪掉 31% 的病人**。
   → 一律用 `afp_ge_400`（二元），這也是 PSM 唯一需要的。
2. **單位。** Beta 那三家（H02/H05/H08）的 albumin 是 **g/L**（要 ÷10）、
   bilirubin 是 **µmol/L**（要 ÷17.1）。忘了換算不會報錯，只會讓 albumin 變成 40 g/dL，
   然後 PSM 的結果一路歪掉。
3. **醫院本身就是干擾因子。** 學術中心 H01 有 65.9% 的病人用 atezo+bev，
   社區醫院 H07 只有 34.7%。醫院同時決定「用哪種藥」和「病人多重」。
   `hospital_region` / `hospital_type` **不在病人檔裡**，在 `hospitals_meta.csv`，必須 join。
4. **審查（censoring）是真的。** 不可以用「死亡數 ÷ 總人數」當死亡率。必須 Kaplan–Meier。
5. **這是合成資料。** 模擬自 Finn RS et al., NEJM 2020;382:1894。
   不構成任何關於 atezolizumab–bevacizumab 或 sorafenib 的證據。
   **手稿的標題、摘要與正文都必須寫清楚**（驗收會檢查三個地方）。
6. **引用不准憑記憶生成。** 第 06 章每一筆參考文獻都要先 WebSearch 找到真的文獻，
   再用 Crossref API 驗證 DOI 與六個書目欄位。**驗不過就從稿子裡刪掉。**
   看起來很專業的 DOI 不等於存在的 DOI。
7. **每改一輪字，就重跑一次數字稽核。** 第 07 章會改四輪（回應審稿、潤稿、去 AI 腔），
   每一輪之後 verify 都會重驗數字有沒有被改壞。這是本教材的主軸。

## 環境

Python 用 repo 根目錄的 venv：`../.venv/bin/python`（已裝好 pandas / numpy /
lifelines / matplotlib）。若不存在，跑 `make setup`。
第 08 章另外需要 `pandoc`、`tectonic`、`rsvg-convert`（或 `inkscape`）。

**上台前先跑這個**，把所有「現場才會發現」的問題提前引爆：

```bash
cd live-demo && ../.venv/bin/python verify/preflight.py          # 現場路線
cd live-demo && ../.venv/bin/python verify/preflight.py --full   # 完整路線
```

它會實際呼叫一次 `add_at_risk_counts()` 看會不會崩、確認 tectonic 已暖機
（首跑要下載套件包 ~20 秒）、確認 Crossref 連得到、確認沙盒是空的。
**綠燈才上台。**
